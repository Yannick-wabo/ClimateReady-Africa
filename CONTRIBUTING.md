# Contributing

1. Create a branch from `main`.
2. Keep changes within the agreed product scope.
3. Add or update tests when scoring, validation or persistence behaviour changes.
4. Run `npm run check` before opening a pull request.
5. Explain any change to weights, thresholds, criteria or pathway applicability in the pull request.
6. Never include real credentials, confidential evidence or unverified regulatory claims.

Commit messages should be short and describe the resulting change, for example `Add evidence validation test` or `Clarify PACM authorisation guidance`.
